# game-team-protocol — 절차를 지키며 작업하기 (Codex)

이 스킬은 `<팀저장소>\PROTOCOL.md`의 실행 요약이다. 충돌하면 PROTOCOL.md 원본이 우선한다. 팀 저장소 찾기는 AGENTS.md 참조.

## 0. 행위자 표기 (항상)

역할명에 `-codex` 접미사: `gameplay-programmer-codex`, `main-codex`(조율자). 타임라인·커밋 메시지·지식 기록의 행위자 표기에 모두 적용.

## 1. 작업 시작 절차

1. `git -C <팀저장소> pull --rebase` — 원격 없음/실패 시 그대로 진행하되 보고에 명시.
2. `<팀저장소>\GLOBAL_RULES.md` 읽기 — 전역 금지·강제 위반 작업은 수행하지 않는다.
3. **동결 게이트 확인**: `knowledge\<프로젝트명>\docs\01-planning\plan-frozen.md`가 채워져 있는가?
   - 비어 있으면(틀만 있으면): 신규 기능·구조 변경 구현 금지. 기획 단계가 필요함을 보고. (버그 수정·소규모 유지보수는 허용 — 동결 전임을 보고에 명시)
4. 역할 채택: `<팀저장소>\agents\<역할>.md` 전문 + `engines\<엔진>.md` 플레이북(공통 + 자기 역할 섹션) 읽기.
5. 맥락 복원: `knowledge\<프로젝트명>\`에서 `_shared.md` → 자기 역할 지식 파일(`<역할>.md`) → `_timeline.md` 순으로 읽고, 관련 `[[토픽 노트]]`(`notes\`)를 따라가 이전 결정·시행착오를 확인한다. 같은 실수를 반복하지 않는다.
6. `_project.md`의 알려진 경로 목록에 현재 작업 디렉토리가 있는지 확인 — 없으면 같은 프로젝트인지 판단(불확실하면 사용자 확인) 후 경로 추가.

## 2. 작업 중 규칙

- **격리**: 다른 역할의 지식 파일은 읽지도 쓰지도 않는다. 열람 허용: 자기 파일, `_shared.md`, `_project.md`, `notes\`(읽기·쓰기), `docs\`(읽기 전용), `_timeline.md`(읽기 전용 — 쓰기는 오케스트레이터만).
- **기획 문서(`docs\`) 수정 금지** — 기획 변경이 필요하면 멈추고 사용자에게 보고(백트래킹, PROTOCOL 참조).
- 엔진 에디터 전용 직렬화 파일(씬/프리팹/uasset)은 직접 수정을 최소화하고, 필요한 에디터 작업은 "에디터에서 해야 할 일" 목록으로 보고 (GLOBAL_RULES).
- 다른 프로젝트의 지식 폴더 접근 금지.
- Claude Code 파이프라인 산출물(프로젝트 `docs/0N-*/reports/`, `docs/works/`)은 읽기 전용. 그 게이트 승인은 사용자만 한다.

## 3. 작업 종료 절차

1. 자기 역할 지식 파일 맨 위(제목 아래)에 기록:
   ```
   ### [YYYY-MM-DD] 작업 한 줄 요약 (행위자: <역할>-codex)
   - **진행 상황:** / - **결정과 이유:** / - **시행착오:** / - **남은 일:**
   ```
2. 관련 개념에 `[[위키링크]]`, 두 번 이상 등장했거나 남에게도 유용한 지식은 `notes\<토픽>.md`로 승격.
3. 다른 역할도 알아야 할 내용(아키텍처 규칙·공용 API 변경·컨벤션)은 `_shared.md`에 승격.
4. 오케스트레이터(main-codex)는 `_timeline.md` 끝에 한 줄 추가 (append-only — 기존 줄 수정·삭제 금지):
   `- [YYYY-MM-DD] <역할>-codex: 한 줄 요약 → 관련 [[토픽]] / 후속: 다음 할 일`
5. 커밋: `git -C <팀저장소> add -A` → `git -C <팀저장소> commit -m "knowledge(<프로젝트명>): <역할>-codex - 한 줄 요약"`. 원격이 있으면 push, 충돌 시 rebase로 양쪽 기록 모두 보존.
