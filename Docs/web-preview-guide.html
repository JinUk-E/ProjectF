프로젝트 F — 브라우저에서 플레이하기

PC의 키보드와 마우스로 기존 AI 대전과 같은 PC에서의 2인 대전을 즐기는 웹 버전입니다. 설치 파일 대신 웹 폴더를 호스팅하면 됩니다.

조건부 · 게시 전 확인
실제 브라우저 조작과 공개 URL 검증을 완료한 뒤 게시 완료로 판단합니다. 로컬 브라우저 사용 설정과 별빛공방 주소 확인이 필요합니다.

웹 빌드 성공: 오류 0 · 경고 0 · 약 31MB. 관련 PlayMode 검사 17건(카메라 7 + 최종 메뉴·웹 정지 10), 게시 파일 13건 HTTP·해시·gzip·WASM 헤더·페이지 문법 검사 통과. 실제 브라우저 플레이와 외부 게시는 아직 미검증입니다.

항목동작·검토 기준
범위PC 브라우저, AI 대전, 로컬 핫시트. 모바일 조작과 온라인 매칭은 포함하지 않습니다.
대전 중 이탈탭 이탈·전체화면 해제는 정지. 돌아온 뒤 계속하기를 눌러 재개합니다.
게임 종료페이지에 종료·다시 시작 화면을 표시합니다. 브라우저 창을 강제로 닫지 않습니다.
호스팅웹 폴더 전체를 같은 경로 아래 게시합니다. gzip fallback 파일 .unityweb은 원본 바이트 그대로 제공합니다. 잘못된 Content-Encoding 헤더를 추가하지 않습니다.
캐시Build 파일은 해시 이름, index.html은 갱신 확인이 가능한 짧은 캐시를 사용합니다.
공개 범위실행 파일·라이선스만 공개. 소스는 private 저장소 유지. 빌드 바이너리를 main 히스토리에 커밋하지 않습니다.

로컬 실행

프로젝트 루트에서 node scripts/serve-web.mjs 실행 후 http://127.0.0.1:8173/에 접속합니다. index.html을 파일로 직접 열면 게임 데이터가 로드되지 않습니다.

다시 만들기

같은 프로젝트의 에디터를 종료하고 Unity 6000.5.6f1에 -batchmode -quit -projectPath [프로젝트 경로] -buildTarget WebGL -executeMethod Fortress.Editor.WebPreviewBuild.Build -logFile [로그 경로]를 전달합니다. 결과는 Builds/ProjectF-Web-preview입니다.

이후 pwsh -File scripts/package-web.ps1로 라이선스와 파일 검증·해시 목록을 준비합니다. 결과 요약은 Logs/web-build-result.json에 있습니다. 빌드 도구가 바꾼 설정은 finally에서 복원하지만 강제 종료했다면 실행 전 백업과 비교해야 합니다.

게시용 폴더는 Builds/WebPublish입니다. 패키징은 실행에 필요한 폴더만 복사하며 Unity의 DoNotShip 디버그 폴더는 제외합니다. 기존 WebPublish가 있으면 덮어쓰지 않고 중단합니다.
